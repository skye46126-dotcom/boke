```mermaid
flowchart TD
    A[用户打开站点] --> B[加载 index.html / JS / CSS]
    B --> C[PWA Service Worker 注册并缓存静态资源]
    C --> D[Vue 3 应用启动]
    D --> E[Vue Router 匹配页面路由]
    E --> F{进入的页面类型}

    F -->|Home / About / Projects / Changelog| G[渲染本地静态数据和交互组件]

    F -->|Articles / Search| H{Supabase 是否已配置}
    H -->|否| I[进入降级模式或显示空状态]

    K --> L{是否进入文章详情}

    T -->|是| V[查询 gallery 表]
```

## 2. 架构图

```mermaid
flowchart LR
    subgraph Client[浏览器客户端]
        User[用户]
        Host[Cloudflare Pages 或 Nginx 静态站点]
        SW[Service Worker<br/>静态资源缓存<br/>Supabase 请求 NetworkFirst]
        App[Vue 3 SPA<br/>main.js + App.vue]
        Router[Vue Router]
        UI[页面与组件层<br/>Home / Articles / Gallery / Guestbook / ProjectsIDE]

    end

    subgraph Data[数据服务层]
        Proxy[Cloudflare Worker Supabase Proxy<br/>可选加速层]
        Supabase[Supabase JS Client]
        DB[(Postgres<br/>articles / gallery / guestbook / article_comments)]
        Realtime[Realtime Channels]
        RPC[RPC<br/>increment_article_views]
        Storage[(Storage / image_url)]
    end

    User --> Host
    Host --> App
    App <--> SW
    App --> Router
    Router --> UI
    Search --> UI
    Local --> UI
    Shiki --> UI

    UI -->|默认直连| Supabase
    UI -. 国内加速时 .-> Proxy
    Proxy --> Supabase

    Supabase --> DB
    Supabase --> Realtime
    Supabase --> RPC
    Supabase --> Storage

    Realtime --> UI
    RPC --> DB
```

## 3. 图示说明

- 这是一个 `Vue 3 + Vite + Vue Router` 的单页应用，页面渲染发生在浏览器端。
- `Supabase` 同时承担数据库访问、实时订阅和部分 RPC 能力。
- `Guestbook` 与 `Comments` 都依赖 Realtime 订阅来实现新增内容自动刷新。
- `Gallery` 在未配置 Supabase 时会退回到 mock 数据，`Guestbook` 则进入只读降级模式。
- `Cloudflare Worker` 代理不是强制组件，只在国内访问 Supabase 较慢时作为可选加速层。
- `vite-plugin-pwa` 生成的 Service Worker 会缓存静态资源，并对 Supabase 请求采用 `NetworkFirst` 策略。
